# Move probes -- RFC 0018's baseline

These probes count every constructor, copy constructor, `let` and destructor at each site
named in RFC 0018 ("Move semantics", `docs/architecture/decisions/0018-move-semantics.md`,
local), so that each phase of that work can show **which counts it changed and which it did
not**.

| File | What it pins |
| --- | --- |
| `count.bi` | The counting type `T`. Every object gets a serial number, so a trace says *which* object was copied or destroyed, deterministically. It holds a STRING field, because all-scalar data hides a double free. |
| `sites.bas` | Every site in the RFC's section 5.1. `M*` cases are the ones that **move** after P1, `C*` cases must **keep copying**, and `Q4` is the RFC's open question 4. |
| `implicit.bas` | A UDT with **no structors written by hand** (dynamic array + string + one `T`), returned, assigned and passed by value. It prints the data after each case to show it arrived intact. |
| `relocate.bas` | The relocations FreeBASIC already performs: `swap` and `redim preserve`, with no copy and no `let`. V1 rests on these; V5's `nomove` must close both. |
| `noncopyable.bas` | Returning a type whose copy constructor is private. It is rejected today; under V4 it compiles. The baseline is the diagnostic. |

## The baseline is today's tiko, not fbc

`<name>.p0-trace` is what **tiko** printed at P0 (master `61a0e6813`, 2026-11-27).
`<name>.fbc-trace` is what **fbc 1.20** (fbc-modern) printed. At P0 the two are identical
for every run probe. `noncopyable` differs because tiko rejects it at a different line; see
below.

The RFC changes structor counts **on purpose** (V7). After P1 a diff in an `M*` case is
the expected result, and a diff in a `C*` or `R*` case is a bug. Read the diff case by case.

```
bash build/movetrace.sh            # build + run each probe with bin/tiko.exe, diff against .p0-trace
bash build/movetrace.sh --record   # rewrite both baselines -- only when a phase is accepted
```

## The vendored tests that can see a move

`vendored-candidates.tsv` is generated by `python -I build/movecand.py`. It lists the **83**
files in `tests/vendor/fbc-tests` whose constructor, destructor or `let` bodies print or
count, so they could notice a skipped copy. **29** of them also return or take such a type
by value, which is a V2 site; those are marked `MOVE-SITE`. This is a **heuristic**: P1's
suite run produces the real list.

P0 status of those 29, measured 2026-11-27:

| Lane | Files | Result |
| --- | ---: | --- |
| `build/suiterun.sh <file>`, fbcunit suites | 22 | **22 match fbc**, 0 differ |
| built and run with both compilers, output compared (`COMPILE_AND_RUN_OK` files) | 3 | 3 match (`generics/for-each`, `generics/iterator-protocol`, `pp/typeof-no-dtors`) |
| not run (compile-only or warning tests) | 4 | `structs/base-init-not-first-1`, `syntax/op-cast-private-1`, `syntax/op-cast-private-2`, `warnings/suffix-fb` |

So every file that P1 changes starts out matching fbc, and any difference it shows there is
caused by the move work.

## Every case balances

Each `Report` line ends `balance=ok`: everything constructed or copied was destroyed,
except the objects a case leaves alive on purpose (`shared g, arr`, the `static` in `C9`),
which are counted. A move must keep every line `ok`. An `UNBALANCED` line means an object
was destroyed twice or never, whatever else the trace says.

## Found while recording: `noncopyable` is caught at the link

fbc rejects `return h` with error 205 ("Constructor has no public access", line 31). tiko
does not reject `return h` at all. It rejects the **call site**, `dim as Owner a =
OpenOwner( 42 )`, with TKO0633 (line 34). Without that call site, tiko compiles the function
and fails only at the **link**, `undefined symbol: OWNER::OWNER(OWNER&)`, so `-c` would
accept a program fbc rejects. This existed before RFC 0018. V4 makes `return h` legal, which
closes it from the other side, but until P3 lands it is a D4 accept/reject difference.
