# msvc-manifest.txt -- which abtests can run against the MSVC ABI, and how.
#
# ORIGINAL WORK. Part of libtkogfx (LGPL-2.1-or-later with the static-linking
# exception).
#
# gfxlib2 ships as a MinGW archive. An MSVC-ABI binary cannot link it, so a
# test that calls gfxlib2 in-process cannot be built for MSVC at all. This file
# records, per source, which of three shapes it has. abtest.sh reads it, and
# fails if a source listed as native or split stops building -- so the MSVC
# coverage here can only ever go up.
#
#   native      Calls no gfxlib2 entry point. Builds for MSVC unmodified.
#               These are unit tests of libtkogfx, not A/B comparisons.
#
#   split       Converted to the abtest.bi role model: the gfxlib2 half is
#               #ifdef'd out under -d ABTEST_SUT and its answers come from the
#               recording in golden/ instead. Runs on every ABI.
#
#               Some split tests still contain reference-only cases (Interop_)
#               or reference-supplied seeds (Datum_). Both are counted and
#               printed by the run, so what MSVC actually checked is on the
#               line rather than inferred from the case count.
#
#   mingw-only  Cannot be split, with the reason. Runs in the four MinGW
#               configurations only.
#
# Two remain, and neither is a matter of effort:
#
#   abtest-blit  Its SOURCE DATA is gfxlib2's live framebuffer, dirty array and
#                device_palette, all reached through the ABI seam, and its
#                reference blitter is a function pointer from fb_hGetBlitter.
#                Remove gfxlib2 and there is nothing to blit and nothing to
#                blit it with. Seeding a framebuffer from a recording would be
#                tens of thousands of values and would test the seeding.
#
#   abtest-cells Our cell plane is written FROM the reference: the default
#                fg/bg, and every cell's attribute, are read out of gfxlib2 and
#                stored into our plane, which is then read back and compared.
#                Split, it would seed more values than it compares -- the
#                harness would print more seeds than cases, which is the honest
#                signal that it is not worth doing. What it would still check
#                under MSVC is CellReadXY's packing, and nothing else.
